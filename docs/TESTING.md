# 测试与验证规范

**重要：** 本文定义验证要求，不声称仓库已经具备完整真机测试覆盖。测试文件存在、脚本存在或某次历史工作流成功，都不等于当前提交已通过全部验证。

## 1. 验证级别

| 级别 | 验证内容 | 可以证明 | 不能证明 |
|---|---|---|---|
| L0 静态检查 | diff、格式、敏感信息、资源与 Manifest 审查 | 明显错误和风险得到检查 | 代码可编译或运行 |
| L1 单元/回归测试 | 纯逻辑、映射解析、状态机、数据处理 | 被覆盖逻辑符合断言 | 真实宿主 Hook 生效 |
| L2 Android 构建 | 对目标变体执行 Gradle 构建 | 指定配置可编译打包 | APK 可安装、签名正确或 Hook 生效 |
| L3 APK 检查 | APK 结构、Manifest、DEX、ABI、对齐、签名 | 产物结构及指定属性符合要求 | 真机功能正确 |
| L4 模拟器/沙盒 | 模拟宿主输入、组件交互和兼容分支 | 隔离环境中的行为符合预期 | 真实 DeepSeek/Xposed 兼容 |
| L5 真机验证 | 真实设备、宿主版本、渠道及 LSPosed 环境 | 指定设备组合上的实际行为 | 未测试设备或宿主版本 |

报告结果时必须写明级别、环境、宿主 versionCode、执行命令、结果和未覆盖范围。

## 2. 当前 GitHub Actions

### `ci.yml`：dev 分支 PR 质量门禁

触发：
- Pull Request 目标分支为 `dev`；
- 推送到 `dev`；
- 手动触发。

权限仅为 `contents: read`，不读取正式签名 Secrets，不创建 Release。

当前自动执行：
- Legacy Xposed adapter 回归；
- Expert Relay gate 回归；
- UI 语言目录检查；
- 构建传统 Xposed universal 核心；
- Host V271 与 thinking/feature 回归；
- Open Release Gradle 构建；
- Android Lint；
- APK ZIP、Manifest、DEX、zipalign 和 CI 临时签名检查。

CI 使用临时生成的测试签名密钥。该密钥仅用于验证 APK 可签名，不代表正式发布身份。

### `build.yml`：正式签名构建

正式签名构建仍由原 `build.yml` 管理，触发为 `main` 推送或手动执行。它使用仓库 Secrets 并创建预发布 Release。PR 验证不得调用该流程，也不得获得发布签名 Secrets。

## 3. 修改类型与最低验证

- 纯文档：检查链接、命令、版本号与源码一致性。
- 普通 Java/Kotlin 逻辑：相关单元测试 + 对应构建。
- Hook 目标/映射变化：映射检查 + Hook 回归测试 + 对应宿主真机验证；真机无法执行时明确标记未验证。
- Hook 安装状态/并发/重试：首次成功、重复安装、中途异常、部分失败重试、并发调用。
- IPC/Provider/Receiver/Binder/权限：调用者身份、未授权调用、伪造输入、权限拒绝、最终合并 Manifest 检查。
- 存储/导入导出：空数据、损坏数据、超大数据、路径穿越、旧版本迁移和恢复。
- 构建脚本/Workflow：在干净环境验证目标任务、产物结构、退出码和权限边界。
- Release：APK 完整性、zipalign、签名证书指纹、校验和及安装验证。

## 4. Hook 测试原则

每个新增或修改 Hook 至少覆盖适用的情况：

- 目标类/方法存在且签名匹配；
- 目标类/方法缺失或签名变化；
- 映射表缺失、损坏或版本不匹配；
- Hook 安装抛异常；
- 重复安装和并发初始化；
- 原方法返回值、异常和副作用未被意外改变；
- 可选 Hook 失败时宿主主流程仍可用；
- 关键 Hook 失败时模块状态明确显示失败。

## 5. CI 质量门禁状态

新增工作流文件仅代表门禁定义已提交。首次 GitHub Actions 运行完成前，状态必须标为“待首次运行验证”；不能将 YAML 静态审查当作 CI 已通过。

后续可按失败记录逐项修复基线问题，不得通过删除测试、降低断言或跳过失败步骤制造绿色结果。

## 6. 测试报告模板

每次交付至少记录：

- Commit：
- 变更范围：
- JDK / Gradle / Android SDK：
- DeepSeek 版本与渠道：
- Xposed 框架及版本：
- 命令：
- L0/L1/L2/L3/L4/L5 结果：
- 未执行项及原因：
- 未覆盖风险：

不要用“测试正常”“应该没问题”等模糊措辞代替证据。
