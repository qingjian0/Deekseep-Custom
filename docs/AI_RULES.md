# AI 开发规则

**状态：** 本文定义 AI 参与本仓库开发时的执行约束。它不是对现有自动化能力的描述；未接入 CI 的规则仍需人工执行。

## 1. 任务处理流程

每项任务按以下顺序执行：

1. **定义问题**：复述可观察现象、预期行为、宿主版本、Android 版本和框架环境；缺少关键信息时明确假设。
2. **定位实现**：搜索入口、调用链、状态持有者、宿主映射和相关测试；避免只根据类名或注释推断。
3. **分析风险**：标出 Hook 生命周期、线程、进程、权限、持久化、兼容版本和隐私影响。
4. **制定最小方案**：列出要改文件、预期行为、失败路径和测试方案。
5. **实施修改**：只改完成任务所需内容，保持现有 API 和配置兼容。
6. **验证**：运行可用的构建与测试；对无法运行的验证说明原因和替代证据。
7. **交付**：给出提交、变更摘要、测试证据、未解决风险。

## 2. 事实与证据等级

AI 必须区分：

- **源码确认**：当前分支源码直接证明。
- **自动化验证**：当前提交对应的 CI/测试实际通过。
- **沙盒验证**：在隔离环境或模拟输入中通过。
- **模拟器验证**：Android Emulator 上验证。
- **真机验证**：真实设备、真实宿主版本和真实 Xposed 环境验证。
- **推测/待核实**：尚无足够证据。

不得把源码存在等同于功能可用，不得把编译成功等同于 Hook 生效，也不得把单一宿主版本验证推广到所有版本。

## 3. Android 与 Java/Kotlin 规范

- 保持当前 Java Hook 核心和 Kotlin Compose launcher 的职责边界。
- 遵守 Android 生命周期、线程与主线程约束；耗时 IO、反射扫描和大规模映射处理不得无理由阻塞主线程。
- 资源、Context、ClassLoader 和宿主进程对象必须在正确生命周期使用，避免静态持有 Activity/View 导致泄漏。
- 反射调用必须检查目标存在性、参数签名、返回类型和异常路径。
- Compose UI 状态应有明确所有者；避免在组合阶段执行副作用，使用合适的 effect/lifecycle API。
- 不得为了“现代化”而无目标地重写 Java、引入 DI 或更换 UI 架构。

## 4. Hook 专项规则

- 优先使用仓库已有的宿主版本识别与映射机制；不允许将单版本类名硬编码后直接用于其他版本。
- 对每个 Hook 记录：目标版本、符号来源、参数/返回类型、调用时机、是否必需、失败策略。
- Hook 前检查目标类/方法及其特征；映射不可信时禁用该 Hook，而不是猜测近似目标。
- before/after/replace Hook 必须说明对原方法执行的影响；避免无意改变原始返回值、异常和副作用。
- 共享状态必须考虑重复初始化、并发安装、部分失败和重入。
- 可选 Hook 失败时允许宿主继续运行，但必须留下可定位的诊断信息；关键 Hook 失败不能伪装为整体成功。
- `LegacyXposedModule.Hooker.isRequired()` 默认返回 `false`：默认按可选 Hook 处理，单个拦截器异常时跳过该拦截器并保留原方法结果；真正影响宿主关键链路的 Hook 必须显式覆盖为 `true`，其失败应向上暴露。`VirtualMachineError` 和 `ThreadDeath` 不得被 fail-open 吞掉。
- 修改安装状态、安装锁或重试逻辑时，验证首次成功、重复调用、中途异常、部分成功后重试和并发调用。

## 5. 安全与隐私规则

- 所有导出组件都按不可信外部调用设计；不能把静态常量 Token、Binder Descriptor 或包名单独视为强身份认证。
- IPC 应按最小权限原则设计；在可行时校验 UID、包名及签名证书，并考虑权限声明与最终合并 Manifest。
- 新增权限必须说明用途、最小范围和撤销/关闭方式。
- 不得将聊天内容、账号数据、Token、设备标识写入普通日志或远程服务。
- 导入导出必须校验文件类型、大小、路径和数据结构，避免路径穿越、覆盖任意文件和资源耗尽。
- 高风险能力默认关闭；用户确认不能成为不安全实现的替代品。

## 6. 兼容性与映射

- 兼容性以明确的宿主 versionCode、渠道和签名/包信息为边界。
- 新增映射需记录来源、生成方式和验证结果；不能仅凭混淆名称相似判断。
- 未知宿主版本默认不启用不确定 Hook。
- 更新映射时保留旧版本行为，除非任务明确要求移除并有迁移说明。

## 7. 测试与提交

- 修复 Bug 时优先添加能复现旧行为的测试，再修复实现。
- 测试必须验证行为和失败路径，不应只验证类存在或字符串包含。
- 测试不可运行时，说明缺失环境、未覆盖范围和风险，不得伪造通过状态。
- 一个提交聚焦一个逻辑问题；行为变更同步更新文档和 CHANGELOG。
- 详细验证级别见 [TESTING.md](TESTING.md)。
